# Signer Sidekick v2.3.0

Automatic reward runs, using the same gas wallet and transaction engine as manual runs.

- **Opt-in automation:** enable under Settings → Reward runs to calculate, collect, distribute
  and finish Bitcoin payouts without reopening the browser. Default check interval: 15 minutes.
  Settings and Activity show progress; restart preserves the schedule. Admin actions, withdrawals
  of your fees, wallet funding and sweeps remain manual.
- **Stopped work requires review:** no automatic resume or replacement. Unresolved attempts from
  expired or cancelled manual runs also block new scheduled work.
- **Bitcoin payout status:** ledger reads use the registry reported by the deployed PoX-5 contract,
  including custom profiles and Devnet.

Enabling covers future eligible stakers and subsequent chunks. Existing fee limits apply, but there
is **no aggregate spending budget**. Disabling the schedule stops new approvals, not approval already
begun or approved execution. Force Observe stops new signatures; neither undoes a broadcast. See
[automatic reward runs](https://github.com/stx-labs/signer-sidekick/blob/v2.3.0/docs/operator/operations.md#automatic-reward-runs).

## Upgrade

Back up the database, gas-wallet key and configuration, then set `SIDEKICK_IMAGE_TAG=2.3.0` and follow
[Operations](https://github.com/stx-labs/signer-sidekick/blob/v2.3.0/docs/operator/operations.md#upgrade).
Upgrading from 2.2.0 does not enable automation. Schema 44 adds schedule persistence without
rewriting financial rows. Older images cannot open it: rollback requires a compatible database,
without discarding newer approvals or transaction evidence.
