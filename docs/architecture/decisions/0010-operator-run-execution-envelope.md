# ADR 0010: Operator-run execution envelope

- Status: Accepted
- Date: 2026-08-22
- Tracking: [#34](https://github.com/stx-labs/signer-sidekick/issues/34)

## Context

PoX-5 reward handling is a set of permissionless calls — `calculate-rewards` (PoX-5), manager
`claim-rewards`, `claim-staker-rewards`, `settle-accepted-withdrawal`,
`reclaim-failed-withdrawal`. None checks an admin, none moves the caller's own assets, and payouts
are fixed to the named staker. The Stacks Core team is expected to automate these calls
network-wide; Sidekick's flow exists for a pool's first distribution and as a backup when this
signer's calls were skipped.

ADR 0009 establishes the evidence-first ledger. This decision adds only the authority needed for
operator-triggered, occasional, permissionless calls.

## Decision

1. **Operator-run is explicit.** Sidekick may sign the permissionless reward calls with a dedicated
   **gas wallet** only after the operator approves one sealed recipe. Observe remains the default.
   Unattended execution is out of scope and requires a new ADR and security review.

2. **Gas wallet.** Generated by Sidekick (never typed or pasted), written atomically to a fixed
   internal path with owner-only permissions, enabled by a deliberate second step, and hot-activated.
   **Before every run** Sidekick checks and refuses to sign if the address is currently a manager admin, the
   signer principal, or a contract principal. The blast radius is the gas balance. A **Sweep
   remaining STX** function (own sealed `gas-wallet-sweep` plan and authorization variant) is the
   only path that moves the wallet's own asset.

3. **Authorization is a sealed recipe per run.** A run seals manager, network, cycle,
   distribution, the ordered allowed operations, the exact `(staker, cycle, bucket)` account set
   with a maximum entitlement per account, the reviewed total and count, transaction cap,
   per-transaction fee cap, gas budget, fixed recipient/asset semantics, and adapter/source
   identities. Payment children are materialized only after the collect is included and the fee
   snapshot is proven; a child may disappear, shrink, or be skipped, but a run never adds a
   recipient or increases an approved amount. One active authorization per gas wallet (run or
   sweep). Approval must start within 30 minutes; a run may take at most 6 hours; a fee-cap change
   requires re-approval; the per-run transaction cap is presented honestly.

4. **Execution.** Sequential, one transaction in flight, last-moment authoritative revalidation
   before each child, deny-mode post-conditions per adapter (including the reclaim refund), no
   retry and no blind replacement, halt on ambiguity with an exact resume count, durable run
   cursor. Another caller completing work — before or after broadcast — is normal external
   completion, never a failure.

5. **Adapters.** A closed, code-backed registry of the five reward adapters and one explicit signer
   method per adapter. No generic signing or contract calling.

6. **Ledger.** Distributions inside cycles, derived from chain evidence at read time; the seam
   rule for payments spanning two calculations; coverage recorded as `exact` / `combined` /
   `historical-coverage-incomplete` in ledger and exports; a manager-capability matrix; fresh-
   install promises scoped to the recovery boundary; the payment accounting model gross → operator
   fee → staker entitlement → payout (Bitcoin route minus the Bitcoin fee budget). Financial state
   is separate from execution availability.

7. **Vocabulary and amounts.** Cycle / Distribution / Calculate / Collect / Distribute / payments /
   Finish Bitcoin payouts; who and when only in tooltips and exports; amounts below 100,000 sats as
   sats, otherwise 3 significant figures with the unit word (sBTC on Stacks, BTC once out over
   Bitcoin); sorting, filtering, and totals always on integer sats.

8. **Mainnet gate.** A scoped security review approves the exact source fingerprint before
   mainnet operator-run can start. Any source change invalidates that approval automatically;
   Observe and non-mainnet evaluation remain available.

## Consequences

The new authority is bounded by the gas balance and the exact approved recipe. Operators may close
the browser while a run proceeds, but must explicitly resume a halted run. Any future standing or
no-click authority starts as a new design; retired execution mechanisms are not retained as a
compatibility path.
